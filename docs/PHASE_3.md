## 1. Agentic Workflow Overview

VyaparMitra demonstrates genuine agentic behavior rather than a simple chatbot or naive LLM wrapper. The agent orchestrates complex multi-step reasoning, selects deterministic tools with strict inputs, observes quantitative outputs, correlates statutory rules, and drafts actionable communications:

```
[ User Request / Accounting Query ]
               │
               ▼
      ┌─────────────────┐
      │   UNDERSTAND    │  -> Parse intent, fiscal period, scope of reconciliation
      └────────┬────────┘
               │
               ▼
      ┌─────────────────┐
      │      PLAN       │  -> Formulate tool execution sequence & parameters
      └────────┬────────┘
               │
               ▼
      ┌─────────────────┐
      │   SELECT TOOL   │  -> Bind to registered deterministic tool
      └────────┬────────┘
               │
               ▼
      ┌─────────────────┐
      │  EXECUTE TOOL   │  -> Run Python Decimal engine, Luhn validator, etc.
      └────────┬────────┘
               │
               ▼
      ┌─────────────────┐
      │     OBSERVE     │  -> Capture exact calculation outputs & match categories
      └────────┬────────┘
               │
               ▼
      ┌─────────────────┐
      │     REASON      │  -> Correlate variances with CGST Sections 16(2)(aa), 50(1)

 [ Human-in-the-Loop Review: Edit | Approve | Reject ]
```

## 2. Strict Deterministic Boundary (Zero LLM Arithmetic)

A core tenet of VyaparMitra is mathematical correctness and audit reliability:
* **The LLM (Gemini):**
  - Analyzes natural language intent.
  - Plans workflow and selects appropriate deterministic tools.
  - Explains technical accounting discrepancies in clear business language.
  - Drafts respectful, statutory-compliant supplier dispute communications.
  - **NEVER** performs arithmetic, tax percentage computations, interest calculations, or match decision logic.
* **The Deterministic Core (`backend/app/tools/`):**
  - Normalizes invoice strings (removes separators, uppercase conversion).
  - Validates GSTIN format and Luhn Mod-36 checksum.
  - Executes exact and fuzzy multi-stage reconciliation matching.
  - Calculates monetary differences and Section 50 interest exclusively using Python's `Decimal` type.

---

## 3. Registered Deterministic Tools

Tools are registered in `backend/app/agent/tools_registry.py` with strict schemas and error-handling wrappers:

| Tool Name | Purpose | Deterministic Guarantee |
| :--- | :--- | :--- |
| `tool_normalize_invoice` | Strips delimiters and standardizes invoice numbers | Pure string manipulation |
| `tool_validate_gstin` | Validates 15-character GSTIN structure & Luhn Mod 36 checksum | Mathematical checksum algorithm |
| `tool_calculate_tax_differences` | Calculates taxable and tax variances across CGST/SGST/IGST | Python `Decimal` arithmetic with tolerance |
| `tool_calculate_section_50_interest` | Calculates interest for delayed filing or tax liability | Formula: $\text{round}(P \times R \times D / 365, 2)$ |
| `tool_lookup_statutory_rule` | Fetches rule reference, risk description, and statutory citations | Decoupled metadata catalog |
| `tool_run_reconciliation` | Runs full reconciliation between purchase register and GSTR-2B | Multi-stage deterministic matching engine |

## 4. Gemini SDK Integration & Graceful Fallback

* **Official SDK:** Uses Google's official `google-genai` SDK (`google-genai==2.26.0`).
* **Environment Variable:** Reads `GEMINI_API_KEY` strictly from the environment; keys are **never** hardcoded or logged.
* **Model Configuration:** Configured to `gemini-2.5-flash` via `backend/app/config.py`.
* **Graceful Fallback:** If `GEMINI_API_KEY` is absent or the external service is unavailable, the orchestrator seamlessly generates deterministic natural language summaries and dispute notices without crashing or halting execution.

---

## 5. Loop Bounds & Safety Controls

To prevent runaway agentic loops, cost overruns, or hallucinated infinite chains:
* The orchestrator enforces an upper limit of **5 iterations** (`MAX_AGENT_ITERATIONS = 5`).
* Any abnormal iteration depth automatically concludes tool execution and proceeds directly to synthesize findings.

---

## 6. Mandatory Human-in-the-Loop (HITL) Controls

All actions generated by VyaparMitra are strictly advisory:
* Every supplier dispute notice is created with status:
  `DRAFT — REQUIRES HUMAN REVIEW`
* The user is provided four explicit actions:
  1. **Review:** Inspect details, cited sections, and at-risk amounts.
  2. **Edit:** Directly modify notice subject and text in the browser.
  3. **Approve:** Authorize notice for dispatch.
  4. **Reject:** Dismiss or archive dispute communication.
